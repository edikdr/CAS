# HAOTICA — где остановились и что делать дальше

## HAOTICA Terminal для Windows (ветка `terminal-windows`, 2026-11-05)
Сделано по ТЗ `docs/TZ-terminal-windows.md` (M0–M8), описание — `docs/WINDOWS.md`, кнопки — `docs/UI-INVENTORY.md`.
Работа шла в облачном Linux-контейнере: Windows-части проверены CI на `windows-latest` (pytest: ConPTY + pwsh/cmd,
Job Object, keyring, агент с ложной моделью; Playwright; сборка PyInstaller + Inno Setup), но **не на ноутбуке**.
Проверить на железе: окно Qt (рамка, перетаскивание, трей), ConPTY в окне, AltGr/IME, мышь в TUI, vttest,
перетаскивание из Проводника, llama.cpp Vulkan на Radeon 8060S (`haotica llama bench`), голос (winsound), установщик.
Ждёт решения пользователя: победитель слепого теста TTS (`samples/tts/index.html`, ключ — `samples/tts/key.json`)
→ `haotica.tts_engine` по умолчанию и `haotica voice install <движок>`. HIP-сборка llama.cpp для Windows в релизе
b12032 не найдена — только Vulkan (HIP можно задать адресом и SHA-256 в настройках).

Состояние на 2026-11-04. Первая установка на Legion 7 15ASH11 (Arch) показала: система поднимается и выглядит как задумано,
но «сырая». Здесь — известные проблемы, факты о железе и план работы. Читать вместе с `docs/HANDOFF.md`.

## Что работает (подтверждено на железе)
- Установщик (16 модулей) проходит; `--dry-run` и повтор безопасны. Исправлены: `set -e` в detect_cameras, `spirv-headers` для llama.cpp.
- Hyprland + Quickshell запускаются вручную (`start-hyprland` из консоли), оболочка, док, HUD, терминал HAOTICA со всеми панелями.
- `haotica doctor`: ядро/оболочка/агент active, GTT 47 ГиБ, Vulkan RADV, звук, камера, все три модели скачаны.
- llama.cpp b12032 (Vulkan) собран; сервисы моделей должны подниматься агентом сами (не проверено до конца).

## Известные проблемы (по приоритету)
1. **Вход через greetd → чёрный экран.** После пароля сессия Hyprland не создаётся (в `~/.cache/hyprland` ничего нет, сессии пользователя в журнале нет).
   Нужно: `journalctl -b -u greetd`, `which start-hyprland Hyprland`. Подозрение: greeter вызывает `start-hyprland` (greeter/shell.qml:300),
   а `greetd` его не находит/не запускает; или сессию надо оформить как `.desktop` + `command=` в config.toml. Проверить PAM greetd.
2. **Программы из AUR не поставились** (Chrome, Spotify, VS Code, Claude Code): `40-apps` считает AUR-сбой предупреждением и отчитывается «OK».
   Нужно: прогнать `bash install.sh --yes --only 40 --force`, снять ошибку paru; сделать так, чтобы модуль честно показывал, что не поставилось.
   Заметка: Discord/Telegram идут из pacman — проверить, поставились ли.
3. **«Многое в интерфейсе не работает»** — список не получен. Собрать: что именно не открывается/не нажимается (лаунчер, док, панели, настройки, горячие клавиши).
4. **Haotica**: llama-server теперь есть; проверить `?? привет`, переключение base/deep, карточки [TAB]/[ESC], загрузку модели.
5. Голос (Chatterbox/Piper) установлен, но не проверен: `haotica-tts`, «Проверить голос» в Настройках.
6. Подсветка клавиатуры — Fn+Пробел (аппаратно); интеграция с темой не проверена.
7. UMA Frame Buffer в BIOS = 8 ГБ: советовать 512M/Auto (больше общей памяти под модели).

## Уроки установщика
- В `set -Eeuo pipefail` строка `[[ тест ]] && команда` в конце функции убивает скрипт молча: использовать `if`.
- Верхний ERR-trap в `install.sh` теперь печатает место остановки — оставить.
- Модули с некритичными сбоями должны возвращать ошибку (иначе `OK` вводит в заблуждение).
- Всё, что вводит человек, должно быть коротким: ловить опечатки (раскладка!) — предлагать ссылки/ярлыки, а не длинные команды.

## Среда для работы без железа (идея)
- **WSL2 + WSLg** (Windows): запускать core/agent/приложения HAOTICA (PySide6, Python) и править веб-часть; быстро, с мышью.
  Не покажет: Hyprland, Quickshell, greetd, шейдеры экрана, Vulkan-ускорение моделей.
- **Полная VM с Arch** (VMware/VirtualBox): ставить `install.sh` целиком; Hyprland в VM требует 3D-ускорение и часто нестабилен
  (в крайнем случае `WLR_RENDERER_ALLOW_SOFTWARE=1`); GPU-ускорения llama.cpp не будет — проверять модели на CPU маленькой моделью.
- **Реальное железо** остаётся единственным местом для проверки: GPU, шейдеры, greetd, питание, подсветка. Лучше dual-boot (Windows + Arch).
- Claude Code на самой машине (читает логи и правит репозиторий) эффективнее фото экрана.

## Windows: что осталось после первой установки (ноябрь 2026, ноутбук владельца)

Состояние: сборка из CI ставится и запускается, оболочки стартуют (`haotica doctor` → «СТАРТ · … OK»),
ядро и агент поднимаются, окно рисуется. Проверять — на самом ноутбуке (Windows 11 26300, Radeon 8060S, 56 ГиБ),
журналы: `%LOCALAPPDATA%\Haotica\logs` (`window-terminal.log`, `core.log`, `agent.log`, `models-*.log`).

1. **Haotica не видит терминал и не пишет в него.** Агент выбирает инструменты по `engine.hub_has_exec_listener()`:
   terminal_run есть, только если страница терминала подписана на тему `exec` (`HY.stream(["exec","exec_cancel"], …,
   HY.haoticaUrl)` в `apps/terminal/terminal.js`). Проверить: открыт ли поток к агенту (:47810) из окна
   (в `window-terminal.log` нет ошибок EventSource?), доходит ли `exec` до `onExec`, возвращается ли
   `/api/terminal/result`. Видеть вывод — через `terminal_poll`/результат блока: OSC 133 должен работать в
   Windows PowerShell 5.1 (профиль по умолчанию у владельца — PowerShell 7 не установлен).
2. **Нет голоса.** Служба речи ставится отдельно: `haotica voice install chatterbox` (`core/haotica/tts/runtime.py`,
   через uv). Проверить, что uv есть/скачивается на Windows; поставить голос в мастере первого запуска автоматически.
3. **Модель deep (80B) показана готовой, но не скачана.** Сравнить `models.status()` с файлами в
   `%LOCALAPPDATA%\Haotica\data\models` (размер, `.part`, `.lock`); готовность должна требовать полный файл.
4. **Qwen3.8-27B ≈ 10 ток/с.** Для плотной 27B на iGPU это близко к пределу полосы памяти. Быстрый путь — deep
   (80B-A3B, MoE ≈ 3B активных) и драфт-модель (`server_args`, `draft`). Замер: `haotica llama bench`.
5. Режим «без видеокарты» (`--safe-gfx`) включается сам при чёрном окне; флаг — `%LOCALAPPDATA%\Haotica\state\gfx-safe`.

### Итог проверки на ноутбуке (2026-11-06)
1. **Терминал для Haotica — работает.** Причина: политика PowerShell Restricted (Windows 11 по умолчанию) не давала
   загрузить `haotica.ps1` → не было OSC 133 → «вкладка занята». Интеграция теперь передаётся текстом
   (`-EncodedCommand`, политика не меняется); без PSReadLine (pwsh 7 при Restricted) конец команды — по истории.
   Новый инструмент `terminal_read` (экран и блоки с кодами выхода); команду берёт одно окно (`/api/terminal/claim`).
   Проверено: цепочка «создать папку → показать» во вкладке HAOTICA с карточкой на изменение.
2. **Голос Сары — есть** (Chatterbox, CPU): ставится мастером/кнопкой/`haotica voice install chatterbox`, служба
   поднимается с Haotica, образец читается без ffmpeg. Тон −2,5 (≈200 Гц). **Медленно:** синтез ≈ 4× дольше звучания,
   поэтому вслух — начало ответа (`haotica.voice_max_chars`). PyTorch ROCm 7.2.1 для Windows видит Radeon 8060S, но
   Chatterbox на нём не работает (MIOpen `miopenStatusInternalError`, rocFFT зависает, генерация не останавливается) —
   вернуться, когда выйдет новый ROCm для Windows/драйвер.
3. **Deep была скачана целиком** (SHA-256 совпала) — не помещалась в память (f16-кэш 128K, 2 слота, `-ngl 999`).
   Теперь `--fit`, 1 слот, 8-битный кэш, авто-уменьшение контекста при нехватке памяти; «готова» = SHA-256 сошлась.
4. **Скорость** (Vulkan, b12032): base ≈ 9–10 ток/с без драфта (предел полосы памяти), с DFlash n-max 3 — код 13–17;
   deep ≈ 41 ток/с. Главное ускорение — кэш промпта: время и метрики ушли из системной инструкции, инструкция
   прогревается после загрузки — первый ответ 24 с → 5,6 с. Deep основной в «авто» только при ≥ 80 ГиБ ОЗУ: на 56 ГиБ
   deep (42 ГБ) + голос (8 ГБ) + браузер оставляли ~1 ГБ. Совет: UMA Frame Buffer в BIOS — 512M/Auto (сейчас 8 ГБ).
5. Найдено и исправлено: двойная запись журналов agent/core, ложное «драфт не поддержан» после нехватки памяти,
   бесконечные перезапуски llama-server, «0%» GPU и памяти в окне (PDH), разбор PowerShell по `;` внутри `@{…}`,
   «папка не разрешена» вместо «не найдена», пересборка обоев Linux в Windows, мастер при каждом запуске гонял всю
   диагностику, ошибка ConPTY при закрытии окна.

Осталось: голос на видеокарте (ROCm/DirectML), меньший вариант deep (UD-IQ4_XS, −4 ГБ) по желанию владельца,
время открытия окна (~3,5 с до страницы при цели ≤ 3 с), `vttest` вручную.
