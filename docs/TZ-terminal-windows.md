# ТЗ: HAOTICA Terminal for Windows (v2)

## 0. Контекст и цель
В репозитории `edikdr/CAS` (ветка `hyprina-os`) есть HAOTICA OS на Arch: терминал (веб-интерфейс на xterm.js в окне PySide6/QtWebEngine), ядро (aiohttp :47800), агент Haotica (aiohttp :47810, llama.cpp), приложения. На ноутбуке Lenovo Legion 7 15ASH11 (Ryzen AI Max+ 392, Radeon 8060S, 64 ГБ общей памяти, экран 2560×1600@165) система поднялась, но получилась сырой. Пользователь переходит на **Windows** и хочет **качественный терминал в стиле HAOTICA с Haotica (локальный ИИ)**: всё, что нравится в Linux-версии (вид, CRT, аватар, блоки команд, Haotica-панель), но как нормальный классический терминал для Windows, с ИИ, который сам выполняет цепочки команд.

**Результат:** установщик `HaoticaTerminal-Setup.exe` (без прав администратора) → окно терминала с PowerShell/cmd/WSL, чат с Haotica, 3 локальные модели для кода, 1 локальная модель речи, файловая панель с превью.

## 2. Архитектура на Windows
Процессы: **host** (окно терминала, PySide6) · **core** :47800 · **agent** :47810 · **llama-server.exe** ×(fast всегда; base ⇄ deep по очереди) на :47822/:47821/:47824 · **tts** :47830. Все слушают только 127.0.0.1, токен в файле `%LOCALAPPDATA%\Haotica\state\token`, заголовок `X-Haotica-Token` (как сейчас).
- Вместо systemd — **супервизор** (модуль `core/haotica/supervisor.py`): запускает/перезапускает дочерние процессы, Job Object (всё закрывается вместе с окном), логи в `%LOCALAPPDATA%\Haotica\logs`.
- Пути (`paths.py`): конфиг `%APPDATA%\Haotica`, данные/модели `%LOCALAPPDATA%\Haotica\data`, состояние/токен/runtime `%LOCALAPPDATA%\Haotica\{state,run}`.
- Секреты: `keyring` → Windows Credential Manager. Корзина: `send2trash`. Открыть файл: `os.startfile`. Уведомления: системный трей PySide6.
- Метрики: `psutil` + счётчики Windows (GPU Engine, GPU Adapter Memory Shared/Dedicated); температуры необязательны (LibreHardwareMonitor — вне MVP).
- Linux-маршруты ядра (`systemctl`, `pactl`, `nmcli`, `bluetoothctl`, `hyprctl`, `secret-tool`, `powerprofilesctl`, `brightnessctl`) — отключаются флагом платформы, UI скрывает соответствующие плитки/страницы.

## 3. Рабочие потоки (W0–W8), требования и приёмка

### W0. Платформенный слой (запуск на Windows)
- T-01 `paths.py`: Windows-ветка (см. §2); `HAOTICA_DEV_ROOT` для разработки сохраняется.
- T-02 ConPTY-сессия вместо `pty.py`: профили оболочек — PowerShell 7 (`pwsh`), Windows PowerShell 5.1, cmd, WSL (по дистрибутивам из `wsl -l`), Git Bash (если есть). Resize, UTF-8, `TERM_PROGRAM=haotica`, завершение всего дерева процессов, обратное давление (как PAUSE_AT/RESUME_AT в `pty.py`).
- T-03 Интеграция оболочки (OSC 133 A/B/C/D, OSC 7 cwd, OSC 7777 текст команды): PowerShell — через функцию `prompt` и PSReadLine, не ломая пользовательский `$PROFILE`; cmd — `PROMPT` с `$E]…` (без блоков команд, но с cwd); WSL/bash — существующий `apps/terminal/shell/bash/haotica.bash`.
- T-04 Запуск `host.py` и вкладок на Windows без отладочных костылей; закрытие окна завершает все дочерние процессы.
- T-05 Режим без моделей: терминал полностью работает без Haotica (молча).
**Приёмка:** `pwsh`, `cmd`, WSL открываются во вкладках; блоки команд, cwd и коды выхода видны; закрытие окна не оставляет процессов (`tasklist`).

### W1. Классический терминал: проверка и доработка («все кнопки и режимы работают, всё как в классических терминалах»)
Первый шаг — составить **`docs/UI-INVENTORY.md`**: таблица всех кнопок, пунктов меню, горячих клавиш и режимов текущего интерфейса с ожидаемым поведением и статусом (OK / не работает / нет). Затем починить и покрыть тестами. Обязательный список (эталон — Windows Terminal / Alacritty):
- T-10 **Ввод:** любые раскладки, **AltGr на немецкой** (`[ ] { } \ @ € ~ |`), «мёртвые» клавиши (`^ ´ \``), кириллица, IME, Ctrl+буква, Alt+буква, F1–F12, Home/End/PgUp/PgDn/Insert/Delete, стрелки с модификаторами; Ctrl+C — прерывание, но **копирует, если есть выделение** (как в Windows Terminal); Ctrl+Shift+C/V — всегда копировать/вставить; Shift+Insert / Ctrl+Insert; настройка «правая кнопка = вставить/меню».
- T-11 **Выделение и буфер:** двойной клик — слово, тройной — строка, Alt+перетаскивание — прямоугольник, Shift+клик — расширить; «копировать при выделении» (настройка); многострочная вставка с предупреждением; bracketed paste; OSC 52.
- T-12 **Прокрутка:** история 10 000–100 000 строк (настройка), колесо, PgUp/PgDn, Shift+PgUp/PgDn, «к концу»; переход по блокам (Ctrl+Shift+↑/↓ — уже есть).
- T-13 **Режимы терминала:** альтернативный экран (vim/nvim, less, fzf, mc, btop4win, `wsl tmux`), мышь для TUI (с Shift — обход), truecolor/256, курсор DECSCUSR (форма и мигание), reflow при изменении размера, широкие символы/эмодзи (unicode11), ссылки (OSC 8 и автоссылки), заголовок окна (OSC 0/2), цвета OSC 4/10/11/12, звонок BEL (звук/визуально/выкл).
- T-14 **Вкладки и окна:** создать, закрыть (с подтверждением, если идёт процесс), переименовать, перетаскиванием менять порядок, дублировать, Ctrl+Tab / Ctrl+Shift+Tab, Alt+1…9; **разделение панелей** (горизонтально/вертикально, Alt+Shift+плюс/минус, фокус Alt+стрелки); выбор профиля в «+»; восстановление вкладок и cwd при запуске.
- T-15 **Поиск** Ctrl+Shift+F (регистр, слово, регулярка, подсветка всех совпадений), масштаб шрифта (Ctrl+колесо, Ctrl+0/+/−), полноэкранный режим F11, «всегда сверху».
- T-16 **Настройки терминала** (в `apps/settings`): профили (оболочка, папка, переменные, схема цветов), шрифт, размер, межстрочный интервал, ligatures, прозрачность/CRT, скроллбэк, курсор, звонок, копирование, горячие клавиши (просмотр и переопределение).
- T-17 **Интеграция с Windows:** перетаскивание файла из Проводника → путь в кавычках по правилам оболочки; пункт «Открыть в HAOTICA Terminal» в меню Проводника; команда `haotica .`; запуск от имени администратора по запросу.
**Приёмка:** `vttest` (основные меню) без визуальных артефактов; чек-лист T-10…T-17 пройден вручную и автотестами (Playwright для интерфейса, интеграционные тесты PTY на Windows-раннере); `UI-INVENTORY.md` — ни одной строки «не работает».

### W2. Мини-чат Haotica (замена окошка ввода слева сверху под аватаром)
Сейчас: `#h-reply` (одна реплика) + `#h-input` в `apps/terminal/index.html` («hud link»), логика `ask()/reply()` в `terminal.js` (~744–765). Нужно:
- T-20 Вместо них — **мини-окно чата** прямо под аватаром: лента сообщений с **ползунком прокрутки** в стиле интерфейса, пузыри «вы/Haotica», markdown, блоки кода с кнопками «копировать» и «выполнить в терминале», потоковый вывод, строки «шагов» (какие команды выполняла, код выхода), встроенные карточки разрешений [TAB]/[ESC], кнопка «стоп», индикатор набора, автопрокрутка с кнопкой «к последнему».
- T-21 Поле ввода внизу окна: многострочное (Enter — отправить, Shift+Enter — перенос), `/deep`, `/base`, `/new`, `/clear`, прикрепление файлов (из файловой панели, перетаскиванием, вставкой изображения), счётчик контекста, бейдж текущей модели (fast/base/deep) с переключением.
- T-22 **История чатов:** выпадающий список/ящик внутри мини-окна: поиск по чатам, новый чат, переименование, закрепление, удаление, экспорт (Markdown/JSON); автоназвание чата быстрой моделью после первого ответа; последний открытый чат запоминается. Окно можно развернуть в большую панель (вкладка HAOTICA справа и приложение `assistant` показывают тот же чат).
- T-23 **Хронология одного чата:** бесконечная прокрутка вверх (подгрузка порциями), разделители дат, время, стабильные идентификаторы, «повторить ответ», «копировать сообщение», шаги инструментов сохраняются и показываются после перезапуска.
- T-24 Бэкенд (`core/haotica/agent/server.py`, `memory.py`): `GET/POST /api/chats`, `PATCH/DELETE /api/chats/{id}`, `GET /api/history?chat=&before=&limit=`, `GET /api/chats/search?q=`, `GET /api/chats/{id}/export`; миграция схемы (`messages.extra` хранит шаги); сводки старых сообщений остаются (`summary`).
**Приёмка:** чат переживает перезапуск; 1000 сообщений прокручиваются плавно; история, поиск, переименование, экспорт работают; Playwright-тесты на все кнопки мини-окна.

### W3. Haotica выполняет цепочки команд через терминал
Сейчас: `run_command` выполняется в фоне (`tools.py`, `t_run_command`, отдельный subprocess), `suggest_command` только вставляет текст. Нужно:
- T-30 Новый инструмент **`terminal_run(command, reason, tab?, timeout?)`**: агент отправляет событие `exec` в терминал (SSE-тема), терминал **вводит команду в настоящую вкладку** (по умолчанию отдельная вкладка «HAOTICA» — настройка), по завершению блока (OSC 133 D) возвращает `{exec_id, exit, duration, cwd, output_tail}` через `POST /api/terminal/result`; агент продолжает цикл (до 12 шагов, лимит времени, обнаружение зацикливания).
- T-31 **Режимы и разрешения** (как в `docs/DESIGN.md` §16, `tools.needs_card`): наблюдатель / второй пилот / агент; автономия none / readonly / safe. Чтение — само, изменения — карточкой, **опасное — всегда карточкой**; кнопка «выполнить весь план» одним подтверждением, но опасные шаги подсвечиваются отдельно.
- T-32 **Классификатор команд под Windows** (`agent/safety.py`): PowerShell (`Remove-Item -Recurse -Force`, `Format-Volume`, `Clear-Disk`, `Stop-Computer`, `Set-ExecutionPolicy`, `reg delete`, `iex (iwr …)`), cmd (`del /s`, `rd /s`, `format`, `diskpart`), WSL-bash (как сейчас). Всегда закрыто: `ALWAYS_DENIED` (в т. ч. браузерный профиль банка и `%APPDATA%\…\Credentials`).
- T-33 **Безопасность вывода:** весь вывод до модели проходит `safety.redact`; ограничение 12 КБ; вывод интерактивных/полноэкранных программ (alt-screen) не отдаётся — Haotica спрашивает, запускать ли; долгие команды (>timeout) — «запустить и опрашивать».
- T-34 **Управление:** кнопка «стоп» и Esc отправляют Ctrl+C и отменяют ожидающие шаги; журнал каждого выполненного агентом шага (jsonl + вкладка LOG), шаги видны в мини-чате.
- T-35 В системный промт добавляется тип оболочки (PowerShell/cmd/bash), текущая папка (OSC 7), ОС Windows.
**Приёмка:** сценарий «создай папку, клонируй репозиторий, установи зависимости, запусти тесты» выполняется самостоятельно в видимой вкладке с карточками там, где нужны; опасная команда никогда не запускается без явного подтверждения (тест с `Remove-Item -Recurse C:\…`).

### W4. Модели кода (3 шт.) и ключ рядом с моделью
- T-40 Роли как сейчас: **fast** (Qwen3-1.7B — подсказки в строке), **base** (Qwen3.8-27B, зрение, «мысли» по запросу), **deep** (Qwen3-Coder-Next 80B-A3B). base ⇄ deep по очереди (общая память 64 ГБ), fast всегда рядом; роутер `LLM.route` сохраняется.
- T-41 **llama.cpp для Windows:** готовые релизы (закрепить тег; SHA-256), собрать-не-надо; выбрать между Vulkan и HIP/ROCm-сборкой по замерам на Radeon 8060S; запуск через супервизор (не `os.execv`), `models.launch` и `llm.py` переписать без systemd.
- T-42 Загрузка моделей с докачкой и проверкой SHA-256 (`models.py` уже умеет), прогресс в блоке «DL» и в Настройках; мастер первого запуска предлагает набор (минимум: fast+base; deep — по желанию).
- T-43 **Ключ вместо окна:** убрать модальный `apps/_ui/keys.js` и вызов `keysDialog` из палитры/окна ассистента. В Настройках → Haotica → Облако и в шапке панели HAOTICA — строка `[облачная модель ▾] [поле ключа ••••] [Проверить] [✓/✗ баланс]` **рядом с выбором модели**; ключ хранится в Credential Manager, показывается только маска; команда палитры «/key» просто фокусирует это поле. Аналогично поле ключа ElevenLabs рядом с выбором движка речи (необязательный облачный вариант).
**Приёмка:** три роли стартуют/переключаются без ручных действий; ключ вводится в одну строку рядом с моделью; модальных окон ключа в проекте нет.

### W5. Синтез речи — приоритет «качество»
- T-50 **Одна локальная модель речи** (плюс лёгкий запасной вариант без качества не нужен как основной). Выбор — **по результатам прослушивания**, а не по названию. Первым делом сессия готовит **пакет образцов**: по 12 фраз (русский, английский, немецкий; числа, сокращения, английские слова в русском тексте, вопрос/восклицание, длинное предложение) для каждого кандидата → папка `samples/tts/<модель>/` + страница-плеер; пользователь слушает вслепую и выбирает.
- T-51 Кандидаты (актуальность и наличие проверить поиском в начале сессии): Chatterbox Multilingual (текущий), XTTS-v2, F5-TTS (с русскими дообучениями), Fish Speech/OpenAudio, Orpheus (мультиязычные), Silero v4 (русский), Piper (ориентир «минимум»), новые модели 2026 года. Критерии: естественность и интонация на **русском** (главный язык), английский/немецкий, **клонирование голоса Сары** по `assets/sounds/voice/ref_sarah_1.mp3` (13,7 с) и `ref_sarah_2.mp3`, **скорость** (целевое: до первого звука ≤ 1,5 с для фразы ≤ 15 слов; RTF ≤ 0,8), работает на Windows с Radeon 8060S (проверить варианты: PyTorch ROCm для Windows, ONNX Runtime + DirectML, llama.cpp-совместимые TTS-модели, CPU), размер в памяти рядом с LLM.
- T-52 Сервис `haotica-tts` (контракт сохраняется: `POST /tts {text, lang, exaggeration, speed}`, `GET /health`), добавить **потоковую выдачу по предложениям**, нормализацию текста (числа, даты, сокращения, латиница в русском тексте), очередь, **прерывание** (barge-in: новая реплика/ввод/Esc глушит речь), кэш готовых фраз, регулировка скорости/громкости, тихие часы.
- T-53 Воспроизведение на Windows (Qt Multimedia или `sounddevice`) + огибающая для губ аватара (событие `mouth`, уже есть в `agent/voice.py`).
- T-54 Резерв: ElevenLabs (ключ рядом с выбором движка), затем «только готовые реплики» (`assets/sounds/voice/*.ogg`).
**Приёмка:** пользователь выбрал победителя вслепую; на русском нет «роботизированности» и ошибок ударения на тестовом наборе; задержка в пределах цели; речь прерывается; работает без интернета.

## 4. Нерушимые правила (из `docs/HANDOFF.md` §3, адаптированы)
- Банковский профиль (Sparkasse) только в изолированном браузерном профиле, **без доступа Haotica**; `safety.ALWAYS_DENIED` его закрывает.
- Секреты и ключи вычищаются до любой модели (локальной или облачной); ключи только в Credential Manager, не в файлах и не в логах.
- Фильтр опасных команд и карточка подтверждения **всегда включены**, независимо от режима и «характера».
- Облачные помощники (OpenRouter: `deepseek/deepseek-v4.1-flash`, `anthropic/claude-haiku-5.5`) доступны локальным моделям без карточки **только для публичной информации** и с бюджетными лимитами (DESIGN §15.5); всё с локальными данными — карточкой. Отказ провайдера не обходится переформулировкой.
- TLS и подписи не ослаблять. В коммитах, PR и комментариях не указывать идентификаторы моделей; без PR, если не просили; коммит после каждого этапа.

## 5. Этапы и порядок
M0 ветка `terminal-windows` от `hyprina-os`, среда разработки на Windows, `UI-INVENTORY.md`, **замеры/выбор TTS (образцы)** → M1 запуск на Windows (W0) → M2 классический терминал (W1) → M3 мини-чат и история (W2) → M4 команды через терминал (W3) → M5 модели Windows + ключ рядом с моделью (W4) → M6 синтез речи (W5) → M7 файлы и предпросмотр (W6) → M8 установщик, CI, полировка (W7, W8). Обоснование порядка: сначала хороший терминал, потом ИИ вокруг него; выбор TTS стартует рано, чтобы пользователь успел послушать.
